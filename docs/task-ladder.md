# 🪜 阶梯式任务体系设计（入门 / 进阶 / 挑战）

> 草稿，记录设计讨论，防止以后遗忘。

## 目的

让新人在**同一个功能点**上逐级加码，而不是每人各做一个互不相干的小功能。

## 三档定位

| 档位 | 标签 | 定位 |
|------|------|------|
| 入门 | `新手任务` | 一条命令、纯函数（无状态） |
| 进阶 | `进阶任务` | 在原功能上加参数 / 配置 / 状态 |
| 挑战 | `挑战任务` | 要存储、解析、并发、调度或外部依赖 |

三档都叠加 `认领任务` 标签。

## 运行规则

- 每一档都是**独立可认领的 issue**，照旧走 `/receive` 认领，**不动认领管家状态机**。
- 进阶 / 挑战 issue 正文写一行 `前置：#<上一条>`。
- **时机**：进阶 / 挑战**只在整个入门级 PR 全部合并后**才创建。
- 越级抢目前拦不住；若要拦，需给认领管家加「前置未合并不得认领」的校验（可选，未做）。

## 各功能梯度（进阶 / 挑战）

| 功能 | 进阶 | 挑战 |
|------|------|------|
| `/ping` | 回延迟 ms、`/ping N` 连发 | 延迟落盘 `data/`、`/ping stat` 均值·最大·最小 |
| `/猜拳` | `/猜拳 战绩` 记胜负场次 | 连胜称号 + `/猜拳 排行` |
| `/反转` | 多文字变换（`/大小写`、`/摩斯`） | 正确 grapheme 反转（emoji 家族不拆散）+ 变换链 |
| 早安 | 分时段问候 + 文案配置 | 通用「关键词应答引擎」（正则 + 权重随机 + 冷却） |
| `/抽卡` | `/抽卡 十连` + 保底 | 卡池写进 `configs/`、抽卡落盘「背包」可查 |
| `/今日运势` | 分等级 + 同日同人结果固定（按日期+用户种子化） | 持久化 + 历史查询 + 连续参与加成 |
| `/时间` | 多时区 + `/倒计时` | 定时提醒（要后台调度，会碰核心生命周期） |

## 选型标准（本轮沉淀）

给 `/echo`、`/roll` 挑替代功能时形成的标准，后续挑新任务沿用：

- **轻**：一条命令、纯逻辑，别搞状态机。
- **不花哨**：不做「废话文学」那类文案 / 梗图生成器。
- **零知识库**：不想维护语料 / 映射表（`/诗词`、`/拼音`、`/换算` 因此被否）。
- **好玩不死板**：纯算法型（编码 / 进制 / 加密）被否为「太死板」。

被否的候选：`/换算`（要单位表）、`/诗词`（要语料）、`/井字棋`（太重）、`/废话文学`（太花哨）、`/编码`（太死板）。
